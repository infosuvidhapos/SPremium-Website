# SuvidhaPOS Central — .NET 10 LTS + SQL Server + IIS

Production-oriented central admin website/API for SuvidhaPOS licensing and outlet management.

## What is included

- ASP.NET Core **.NET 10 LTS** web app
- Premium responsive dark admin UI
- SQL Server / SQL Express schema
- First-admin secure setup (no default password committed to GitHub)
- Outlet create/edit/block/unblock
- Store Type central control
- License renewal and version increment
- POS device bind/block/unbind
- POS activation + license sync API
- RSA-3072 / PS256 signed license tokens
- POS profile update endpoint that cannot change Store Type or Validity
- Audit logs and admin roles
- GitHub Actions workflow that builds **IIS-Publish** and a verified **SQL Server .bak**
- SQL backup and restore scripts
- IIS setup/configuration PowerShell scripts

## 1. Build on GitHub

1. Create a GitHub repository and upload this whole folder.
2. Open **Actions → Build IIS Package → Run workflow**.
3. Download artifact: `SuvidhaPOS-Central-NET10-IIS`.
4. Extract `SuvidhaPOS-Central-NET10-IIS.zip`.
5. The final artifact is `SuvidhaPOS-Central-NET10-IIS-WITH-SQL-BACKUP`.
6. Inside it, `IIS-Publish` is the IIS website folder and `DatabaseBackup/SuvidhaPremium.bak` is a real verified SQL Server backup.

The GitHub workflow builds `net10.0` on Windows, starts a temporary SQL Server 2019 container on a Linux runner, creates the schema, runs `BACKUP DATABASE`, validates it with `RESTORE VERIFYONLY WITH CHECKSUM`, then packages IIS + the `.bak` together.

## 2. Create SQL database

On SQL Server / SQL Express, run:

`Database/01_CreateDatabase.sql`

If SQL Server is on the **same Windows server** as IIS and you use the default Trusted Connection, also run:

`Database/05_GrantIISAppPool.sql`

If SQL Server is remote, use SQL Authentication or a domain service account instead.

No admin password is seeded. The first administrator is created through the one-time setup screen.

## 3. Configure production settings

From an elevated PowerShell prompt on the server:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Deploy\Configure-Production.ps1 -PublishPath "C:\Sites\SuvidhaPremium" -SqlServer "38.247.131.87,8416"
```

The script writes `appsettings.Production.json` and prints a random **FIRST ADMIN SETUP KEY**. Save that key. Do not commit `appsettings.Production.json` back to GitHub.

If you use SQL authentication:

```powershell
.\Deploy\Configure-Production.ps1 `
  -PublishPath "C:\Sites\SuvidhaPremium" `
  -SqlServer "38.247.131.87,8416" `
  -SqlUser "suvidhapos_app" `
  -SqlPassword "YOUR-STRONG-PASSWORD"
```

After HTTPS certificate binding is ready, add `-RequireHttps`.

## 4. IIS setup

Install the current **.NET 10 Hosting Bundle** on the IIS server first. Then:

```powershell
.\Deploy\Install-IIS.ps1 -PhysicalPath "C:\Sites\SuvidhaPremium" -Port 8080
```

The App Pool is configured as **No Managed Code**. `App_Data` and `logs` get Modify permission for the App Pool identity.

For production, bind an HTTPS certificate in IIS and enable `Security:RequireHttps`.

## 5. First administrator

Open the site. The login page detects that no administrator exists and switches to first-admin setup. Enter:

- Full name
- Email
- Strong password (10+ characters)
- Setup Key generated by `Configure-Production.ps1`

After the first admin is created, first-admin setup closes automatically.

## 6. SQL backup included in every GitHub build

The final GitHub artifact already contains:

```text
DatabaseBackup/SuvidhaPremium.bak
DatabaseBackup/SuvidhaPremium.bak.sha256
DatabaseBackup/BACKUP-INFO.txt
```

This is a real SQL Server backup created during the Action run, not a placeholder. The build uses SQL Server 2019 Developer only as a temporary build engine; the backup contains a clean schema baseline and no production password/secret.

To deploy on Windows SQL Server / SQL Express 2019 or newer:

1. Copy `DatabaseBackup\SuvidhaPremium.bak` to `C:\SuvidhaPOSBackup\SuvidhaPremium.bak`.
2. Run `Database/03_RestoreDatabase.sql` in SSMS.
3. If IIS and SQL Server are on the same machine with Trusted Connection, run `Database/05_GrantIISAppPool.sql`.

A SQL Server backup cannot be restored to an older major SQL Server version than the engine that created it, so this build-generated `.bak` is intended for SQL Server / SQL Express 2019 or newer. The plain `01_CreateDatabase.sql` remains available when a script-based deployment is preferred.

## Important license authority rule

The local POS database must never be the authority for Store Type or expiry. The central server signs the authoritative license payload. The POS should trust only a valid signature from the central public key and should bind that token to its device fingerprint.

Architecture:

`POS → HTTPS IIS API → SQL Server`

There should be no direct internet SQL connection from POS terminals.

## Main POS API endpoints

- `GET /api/pos/public-key`
- `POST /api/pos/activate`
- `POST /api/pos/check`
- `POST /api/pos/profile`
- `GET /health`

## Central connection architecture

POS clients must never connect directly to the Central SQL Server. Every POS talks only to `http://suvidhapremium.suvidhapos.in/` and the Central Website/API connects to SQL using `ConnectionStrings:CentralDb` from `appsettings.Production.json`. If the SQL Server IP or port changes, only the IIS production configuration is updated; deployed POS clients require no SQL endpoint change.
